# File 23 Founder Manual — Version 1.2.0

## Purpose

The Founder workspace is a private federated control surface. It does not replace File 21 publication truth, File 22 Composer, File 19 notifications, File 20 Safe Mode/rollback, File 24 assurance governance or File 25 public presentation.

## Access

1. Sign in through the platform authentication flow.
2. Open `/publishing-dashboard/`.
3. File 00 must currently identify the user as Founder and approved.
4. Sensitive governance actions require current two-factor confirmation where specified.

## Main areas

- **Overview:** provider health, bounded operational summaries and explicit unavailable/stale states.
- **Create:** deep link to File 22; File 23 does not provide a second composer.
- **Workspace/Inventory:** authorized native projections, search, filters, saved views and native destinations.
- **Review/Calendar:** native File 21/provider decisions and schedule operations through versioned contracts.
- **Collections/Knowledge:** File 23-owned organizational metadata and pointers only.
- **Sources/Media/Interactions/Revisions/Notifications:** federated projections; open native owners for authoritative action.
- **Analytics/Reports:** privacy-thresholded aggregates and signed expiring exports.
- **Tasks/Delegations/Automation:** bounded team operations with audit, expiry, revocation and human confirmation.
- **System Status/Settings:** read-first diagnostics, local reversible repair and staging evidence.

## Direct publish boundary

Founder identity alone does not create a generic direct-publish bypass. Direct publication is available only where the native owner declares the operation, File 00/21 policy permits it, current object state/version remains valid and all security/audit gates pass.

## Delegation rules

- Delegate only the smallest necessary action/object scope.
- Set a short expiry and meaningful reason.
- Never use delegation to grant patient access, impersonation, unrestricted export or autonomous publish authority.
- Revoke immediately when no longer required and review audit evidence.

## Staging acceptance

Do not mark File 23 accepted merely because automated tests are green. Record exact source commit, package SHA-256, role/provider/cache/accessibility/backup/rollback evidence and complete `docs/RELEASE-SIGNOFF.md` only after real Hostinger staging journeys pass.

## Incident response

1. Stop the affected File 23 local operation or provider acceptance; do not mutate foreign data.
2. Preserve audit/job/provider-health evidence.
3. Use File 20 for global Safe Mode or platform rollback.
4. Route security/privacy incidents to File 24 governance.
5. Reconcile native provider state before reopening writes.
