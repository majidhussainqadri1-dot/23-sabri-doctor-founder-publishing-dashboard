# File 23 Doctor Manual — Version 1.1.0

## Access and status

The dashboard is private. File 00 must currently authorize the account. Approved/verified doctors receive their own operational workspace; pending or suspended accounts are denied or restricted read-only according to policy.

## Create and edit

- Use **Create** to open the canonical File 22 Composer.
- File 23 does not save a second draft or provide a duplicate editor.
- Edit, preview, submit and publication actions remain with File 22/File 21 or the relevant native provider.
- A verified doctor normally submits for review unless an explicit trusted-publisher policy allows the exact category/action.

## Inventory and saved views

Use Inventory to find authorized native objects by provider, type, status, date and other allowlisted filters. Counts and states are projections; open the native destination for authoritative details. Saved views store filters only and never patient identifiers or private tokens.

## Review and calendar

Doctors may see only the review or schedule operations allowed by current capability, ownership and native policy. Every mutation rechecks current native state/version and may return a conflict if another person changed the object.

## Sources, media, interactions and corrections

These sections show privacy-filtered projections from canonical owners. File 23 does not copy source bodies, media binaries, private delivery links, comments/messages or correction truth. Use native destinations for authoritative action.

## Tasks and delegation

- Create tasks only for legitimate publishing work.
- Keep descriptions free of patient, clinical, credential or message secrets.
- Delegation is bounded, expiring and revocable; it does not transfer authorship or institutional identity.
- Do not delegate publication, export or sensitive access beyond explicit policy.

## Analytics and exports

Analytics are aggregate and may be suppressed below privacy thresholds. Exports are field-filtered, owner/scope-bound, signed and short-lived. Do not redistribute private exports outside their approved purpose.

## Error and weak-connection behavior

- Do not repeat-click a mutation while it is pending; the interface preserves an idempotency key for safe retry.
- A stale/unknown/unavailable label is not approval or publication.
- When a provider is unavailable, wait or use its native interface; do not attempt a workaround through another module.
- Report dead buttons, false success, privacy leakage or repeated conflicts immediately.
