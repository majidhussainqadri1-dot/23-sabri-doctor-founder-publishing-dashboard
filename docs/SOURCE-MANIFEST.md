# File 23 Source and Package Manifest Policy — Version 1.2.1

## Canonical outputs

A successful exact-head release workflow must produce:

1. `23-sabri-doctor-founder-publishing-dashboard-1.2.1.zip` — installable WordPress plugin.
2. `23-sabri-doctor-founder-publishing-dashboard-1.2.1.zip.sha256` — installable package checksum.
3. `FILE23-1.2.1-MANIFEST.sha256` — checksum manifest for every installable plugin file.
4. `23-Doctor-Founder-Publishing-Dashboard-Source-1.2.1.zip` — complete Git-tracked source, tests, workflows and documentation.
5. `23-Doctor-Founder-Publishing-Dashboard-Source-1.2.1.zip.sha256` — complete-source package checksum.
6. `FILE23-1.2.1-SOURCE-MANIFEST.sha256` — checksum manifest for every Git-tracked source file.
7. `FILE23-1.2.1-RELEASE-EVIDENCE.txt` — exact File 23 head and pinned companion heads.

## Installable package inclusion

The WordPress installable ZIP includes only runtime files required by the plugin:

- plugin bootstrap, readme and uninstall entry;
- `assets/`;
- `includes/`;
- `templates/`;
- `languages/` when present.

It excludes tests, GitHub workflows, source-only tools and governance documentation.

## Complete-source package inclusion

The source ZIP is generated from the exact Git commit using `git archive`; it includes every tracked source, test, workflow, tool and document while excluding the `.git` database and untracked build outputs.

## Reproducibility and integrity

- Installable package is built twice from clean directories and must be byte-identical.
- ZIP integrity, canonical top-level folder and embedded Version 1.2.1 metadata are verified.
- Source package is generated from the exact checked-out commit.
- SHA-256 checksum files and per-file manifests are generated by CI.
- Release evidence records the exact File 23, File 00, File 21 and File 22 heads used by the automated contract run.
- Hostinger staging must verify downloaded bytes against these checksums before installation.

## Release law

No hand-edited ZIP is canonical. Any source change invalidates previous checksums, review evidence and acceptance until the exact new head receives a fresh successful workflow and updated sign-off.
